# 신청폼 중앙 패널 비율 일관화 기획

- 작성일: 2026-09-04
- 상태: 코드 반영 · 자동·브라우저 검수 전
- 적용 대상: 데이로그 LIFE NOTE 신청폼 전체 화면
- 기준 컴포넌트: `main.app-panel`

## 1. 문서 목적

화면을 이동할 때 가운데 흰색 박스의 폭과 높이가 크게 달라져 서로 다른 화면처럼 보이는 문제를 줄입니다. 인트로, 질문, 프로그램 안내, 신청 3단계와 완료 화면이 모두 하나의 안정된 프레임 안에서 이어지는 인상을 만드는 것이 목적입니다.

여기서 **가운데 박스**는 선택지나 입력 필드 카드가 아니라, 헤더와 진행 막대 아래에서 각 화면의 본문을 감싸는 바깥 패널인 `.app-panel`을 뜻합니다.

## 2. 현재 구현 진단

현재 `src/App.css`에는 다음 규칙이 적용되어 있습니다.

| 대상 | 현재 값 | 화면 전환 시 영향 |
| --- | --- | --- |
| 기본 `.app-panel` | `width: min(100%, 560px)` | 인트로·질문·안내·완료 화면은 최대 560px |
| `.app-panel.view-contact` | `width: min(100%, 720px)` | 신청 화면 진입 시 최대 폭이 160px, 약 28.6% 증가 |
| 패널 높이 | 콘텐츠 자동 높이 | 문항별 콘텐츠 양에 따라 위·아래 길이가 매번 달라짐 |
| 헤더·진행 막대 | 최대 720px | 기본 패널보다 넓어 좌우 기준선이 맞지 않음 |
| 패널 내부 여백 | 24px → 32px → 36px | breakpoint 통과 시 실제 콘텐츠 폭이 추가로 변함 |

특히 신청 화면은 이미 `기본 정보 → 가능한 일정 → 개인정보 동의` 3단계로 분리되어 있어, 720px까지 별도로 확장해야 할 정보 밀도가 크지 않습니다. 따라서 신청 화면만 넓게 두는 예외를 없애도 현재 흐름을 유지할 수 있습니다.

## 3. 핵심 결정

### 3.1 고정 종횡비가 아닌 공통 프레임을 사용한다

CSS `aspect-ratio`나 고정 `height`로 모든 화면을 동일한 직사각형에 강제로 맞추지 않습니다. 질문 길이, 오류 문구, 브라우저 글자 확대와 모바일 키보드 상태에 따라 필요한 높이가 달라지기 때문입니다. 고정 높이는 내부 이중 스크롤이나 콘텐츠 잘림을 만들 수 있습니다.

대신 아래 세 규칙을 함께 적용합니다.

1. 모든 화면의 **최대 폭을 560px로 통일**합니다.
2. 높이가 충분한 화면에서는 **최소 높이 640px**을 확보합니다.
3. 콘텐츠가 최소 높이를 넘으면 패널 자체가 아래로 자연스럽게 늘어나도록 합니다.

데스크톱 기준 프레임은 `560 × 640px`, 즉 가로:세로가 약 `7:8`인 형태로 보이게 합니다. 이 비율은 짧은 화면의 시각적 기준이며, 콘텐츠를 자르는 강제 비율이 아닙니다.

### 3.2 신청 화면의 폭 예외를 제거한다

- `.app-panel.view-contact`의 720px 폭 규칙을 제거합니다.
- 인트로, 질문, 안내, 신청과 완료 화면을 모두 동일한 `560px` 최대 폭으로 묶습니다.
- 신청 기본 정보의 2열 배치는 각 필드가 읽기 어려워지지 않는 범위에서 유지하되, 실제 검수에서 라벨이나 오류 문구가 자라면 1열 전환점을 `600px`보다 높게 조정합니다.

### 3.3 헤더·진행 막대의 정렬 축을 패널과 맞춘다

- `.app-header`와 `.question-progress`도 최대 폭 `560px`을 기본으로 맞춥니다.
- 브랜드명, 단계명, 진행 막대와 패널의 왼쪽·오른쪽 경계가 한 축에 놓여야 합니다.
- 진행 막대 유무 때문에 패널의 세로 시작점이 달라지는 것은 허용합니다. 빈 진행 영역을 억지로 남기지는 않습니다.

## 4. 크기 규칙

| 환경 | 패널 너비 | 패널 높이 | 내부 여백 |
| --- | --- | --- | --- |
| `< 360px` | viewport에서 좌우 16px을 뺀 100% | 콘텐츠 자동 높이 | 좌우 16px, 상하 20px |
| `360~599px` | viewport에서 좌우 20px을 뺀 100% | 사용 가능 높이 안에서 최소 높이 확보, 콘텐츠 초과 시 확장 | 24px |
| `600~839px` | 최대 560px | 최대 640px까지 최소 높이 확보, 콘텐츠 초과 시 확장 | 32px |
| `≥ 840px` | 560px 고정 상한 | 기준 최소 높이 640px, 낮은 viewport에서는 축소 | 36px |
| viewport 높이 `< 640px` | 너비 규칙 유지 | 최소 높이 해제, 콘텐츠 자동 높이 | 너비 구간 기준 유지 |

높이가 충분한 화면의 구현 기준은 다음과 같습니다.

```css
:root {
  --app-frame-max-width: 560px;
  --app-frame-reference-min-height: 640px;
  --app-frame-outside-space: 156px;
}

.app-panel {
  width: min(100%, var(--app-frame-max-width));
  min-height: min(
    var(--app-frame-reference-min-height),
    calc(100dvh - var(--app-frame-outside-space))
  );
}

@media (height < 640px) {
  .app-panel {
    min-height: auto;
  }
}
```

`--app-frame-outside-space`는 상단 여백, 헤더, 진행 영역과 하단 안전 여백을 합친 초기 기준값입니다. 구현 시 실제 렌더링을 측정해 조정하되, 화면별로 다른 값을 만들지 않습니다.

## 5. 패널 내부 정렬

- `.notebook-page-content`를 세로 flex 또는 grid 컨테이너로 구성해 패널의 최소 높이를 채웁니다.
- 제목과 본문은 위에서 시작합니다. 콘텐츠 전체를 수직 중앙 정렬하지 않습니다.
- 짧은 화면의 주·보조 행동 영역은 남은 공간의 아래쪽에 놓이도록 `margin-top: auto`를 적용할 수 있습니다.
- 오류 문구가 생기거나 `기타` 입력이 열리는 등 콘텐츠가 늘어나면 행동 영역도 아래로 밀리고 패널 높이가 함께 늘어납니다.
- 긴 프로그램 안내와 개인정보 내용은 패널 내부 스크롤을 만들지 않고 문서 전체의 세로 스크롤을 사용합니다.
- 현재 `≥ 840px`에서 사용하는 하단 행동 영역의 `position: sticky`는 유지할 수 있지만, 패널 최소 높이와 함께 적용했을 때 본문을 가리지 않는지 확인합니다.

## 6. 화면별 적용 원칙

| 화면 | 적용 방식 |
| --- | --- |
| 인트로 | 560px 공통 폭과 기준 최소 높이 적용, CTA는 짧은 콘텐츠에서 패널 하단에 안정적으로 배치 |
| 질문 1~5 | 질문 길이와 선택지 수가 달라도 바깥 패널 폭은 동일하게 유지 |
| 프로그램 안내 | 5개 타임라인 때문에 640px을 넘으면 자연스럽게 세로 확장 |
| 신청 1/3 | 560px 안에서 2열 입력을 우선 검수하고, 긴 오류 문구 발생 시 1열 전환 |
| 신청 2/3 | 짧은 콘텐츠여도 공통 최소 높이를 유지해 박스가 갑자기 작아지지 않게 처리 |
| 신청 3/3 | 개인정보 상세 펼침 시 패널 높이 확장, 내부 스크롤 금지 |
| 완료 | 공통 최소 높이 안에서 완료 메시지와 접수번호 카드의 위계를 유지 |

## 7. 반응형·접근성 원칙

- 최소 높이는 `100vh`가 아니라 `100dvh`를 기준으로 계산합니다.
- 320×568, 280×653과 같이 낮거나 좁은 화면에서는 비율보다 콘텐츠 접근성을 우선합니다.
- 모바일 키보드가 열리면 최소 높이를 고집하지 않고 포커스된 입력, 오류와 다음 버튼까지 문서 스크롤로 도달할 수 있어야 합니다.
- 브라우저 200% 확대와 긴 시스템 글꼴에서도 콘텐츠를 숨기거나 잘라내지 않습니다.
- `overflow: hidden`으로 넘친 콘텐츠를 감추지 않습니다.
- 패널 높이 변화에는 별도 애니메이션을 적용하지 않습니다. 높이를 프레임 단위로 보간하면 레이아웃 비용과 멀미 가능성이 커집니다.

## 8. 구현 범위

### 수정 대상

- `src/App.css`
  - 패널·헤더·진행 막대 공통 폭 토큰 추가
  - `.app-panel.view-contact` 폭 예외 제거
  - viewport 높이 기반 패널 최소 높이 추가
  - 내부 콘텐츠와 행동 영역의 세로 정렬 보정
- `src/App.tsx`
  - 원칙적으로 구조 변경 없음
  - CSS만으로 하단 정렬을 만들기 어려울 때 공통 내부 래퍼 클래스만 추가
- `docs/신청폼/구현-현황.md`, `docs/신청폼/변경-기록.md`, `docs/신청폼/검수-결과.md`
  - 구현 완료 후 실제 적용값과 검수 결과 기록

### 변경하지 않는 범위

- 질문 문구, 선택지와 질문 순서
- 신청 데이터 스키마와 Google Sheets 연동
- 컬러, 글꼴, 테두리와 그림자 토큰
- 프로그램 안내 내용과 개인정보 정책
- 페이지 전환 상태와 퍼널 이벤트

## 9. 권장 구현 순서

1. 공통 프레임 CSS 변수와 560px 단일 폭 적용
2. 신청 화면 720px 예외 제거 후 입력 필드 줄바꿈 확인
3. 패널 최소 높이와 내부 행동 영역 하단 정렬 적용
4. 헤더·진행 막대 폭을 패널 기준선에 정렬
5. 대표 viewport와 긴 콘텐츠·오류·키보드 상태 검수
6. 구현 현황, 변경 기록과 검수 결과 문서 갱신

## 10. 완료 조건

- [ ] 인트로에서 완료까지 화면을 이동해도 패널의 좌우 경계가 움직이지 않는다.
- [ ] 신청 화면 진입·이탈 시 패널 폭이 커지거나 작아지지 않는다.
- [ ] 너비 600px·높이 800px 이상인 viewport에서 짧은 화면은 `560 × 640px` 기준 프레임으로 보인다.
- [ ] 콘텐츠가 640px보다 길면 잘림이나 내부 이중 스크롤 없이 패널이 늘어난다.
- [ ] 320×568과 viewport 높이 640px 미만에서 CTA까지 자연스럽게 스크롤할 수 있다.
- [ ] 390×844, 820×1180, 1280×720, 1440×900에서 가로 넘침이 없다.
- [ ] 신청 기본 정보의 라벨, 입력값과 오류 문구가 560px 패널 안에서 겹치지 않는다.
- [ ] 개인정보 상세 펼침, 오류 표시와 200% 확대 상태에서도 콘텐츠가 잘리지 않는다.
- [ ] 입력 중 모바일 키보드가 열려도 포커스 필드와 다음·제출 행동에 접근할 수 있다.
- [ ] `prefers-reduced-motion` 여부와 관계없이 패널 크기 변화에 불필요한 애니메이션이 없다.
