- 기준 컴포넌트: `main.app-panel`

## 1. 문서 목적

인트로부터 신청 완료까지 이동할 때 가운데 흰색 사각형 박스가 모든 챕터에서 동일한 크기로 보이게 합니다. 같은 viewport에서는 콘텐츠 양과 관계없이 바깥 패널의 너비와 높이를 유지하고, 내용이 많은 챕터만 패널 안의 본문 영역에서 스크롤합니다.

여기서 **가운데 사각형 박스**는 선택지나 입력 필드 카드가 아니라, 헤더와 진행 막대 아래에서 각 챕터 내용을 감싸는 `main.app-panel`입니다.

## 3. 현재 상태와 남은 문제

현재 작업 코드에는 다음 항목이 반영되어 있습니다.

- 기본 패널과 신청 패널의 최대 폭을 `560px`로 통일
- 헤더와 진행 막대를 패널과 같은 `560px` 축에 정렬
- 패널에 기준 `min-height: 640px` 적용
- 짧은 챕터의 행동 버튼을 패널 아래쪽에 배치

폭은 이미 같아졌지만 높이는 `min-height`만 사용하므로 콘텐츠가 많은 프로그램 안내나 개인정보 화면에서 패널이 더 길어집니다. 따라서 현재 상태는 **폭 동일화는 반영됐지만 전 챕터 사각형 크기 동일화는 완료되지 않은 상태**입니다.

## 4. 핵심 결정

### 4.1 같은 viewport에서는 바깥 패널 크기를 고정한다

- 모든 챕터가 하나의 공통 `width`와 `height` 계산식을 사용합니다.
- 챕터별 `width`, `min-height`, `height` 예외를 만들지 않습니다.
- 신청 화면만 넓어지거나 프로그램 안내만 길어지지 않습니다.
- viewport가 바뀌면 패널 크기도 반응형으로 바뀌지만, 그 viewport 안에서는 모든 챕터가 동일합니다.

### 4.2 긴 내용은 패널 내부 본문만 스크롤한다

- 바깥 패널의 크기는 유지합니다.
- 제목·선택지·입력처럼 내용이 길어지면 패널 내부의 `.chapter-scroll-area`만 세로로 스크롤합니다.
- 이전·다음·제출 같은 행동 영역은 패널 아래쪽에 고정해 항상 찾을 수 있게 합니다.
- 브라우저 문서와 패널 내부가 동시에 스크롤되는 이중 스크롤은 대표 viewport에서 만들지 않습니다.

### 4.3 모든 기기에서 하나의 고정 종횡비를 강제하지 않는다

데스크톱 기준 크기는 `560 × 640px`이지만, 좁고 낮은 모바일에서도 이 물리 크기를 그대로 강제하지 않습니다. 기기별로 패널 크기는 달라질 수 있으며 **같은 기기·같은 viewport에서 챕터끼리 동일한 것**을 완료 기준으로 삼습니다.

## 5. 패널 크기 규칙

### 5.1 너비

| viewport 너비 | 캔버스 좌우 여백 | 패널 너비 |
| --- | --- | --- |
| `< 360px` | 16px | `calc(100vw - 32px)` |
| `360~599px` | 20px | `calc(100vw - 40px)` |
| `≥ 600px` | 24px 이상 | 최대 `560px` |

### 5.2 높이

패널 높이는 viewport에서 헤더, 진행 영역과 안전 여백을 제외한 값을 사용하되 최대 `640px`로 제한합니다.

| 환경 | 외부 예약 공간 | 패널 높이 계산 |
| --- | ---: | --- |
| 모바일 `< 600px` | 112px | `clamp(320px, 100dvh - 112px, 640px)` |
| 태블릿 `600~839px` | 120px | `clamp(320px, 100dvh - 120px, 640px)` |
| 데스크톱 `≥ 840px` | 160px | `clamp(320px, 100dvh - 160px, 640px)` |

`320px` 최소값은 패널 안에 제목과 최소 조작 영역을 남기기 위한 안전값입니다. 모바일 키보드 등으로 viewport가 이보다 낮아지면 바깥 문서 스크롤을 보조로 허용하되, 챕터별 패널 높이는 계속 동일하게 유지합니다.

### 5.3 구현 기준 예시

```css
:root {
  --app-frame-max-width: 560px;
  --app-frame-height: clamp(320px, calc(100dvh - 112px), 640px);
}

@media (width >= 600px) {
  :root {
    --app-frame-height: clamp(320px, calc(100dvh - 120px), 640px);
  }
}

@media (width >= 840px) {
  :root {
    --app-frame-height: clamp(320px, calc(100dvh - 160px), 640px);
  }
}

.app-panel {
  width: min(100%, var(--app-frame-max-width));
  height: var(--app-frame-height);
  overflow: hidden;
}
```

외부 예약 공간은 모든 챕터에서 같은 토큰을 사용합니다. 구현 후 실제 헤더와 진행 막대 높이를 측정해 값은 조정할 수 있지만, 챕터별 개별값으로 나누지 않습니다.

## 6. 패널 내부 구조

모든 챕터는 다음 세로 구조를 공유합니다.

```text
┌──────────────────────────────┐
│ 챕터 본문 스크롤 영역        │
│  ├─ 캡션·제목·설명           │
│  ├─ 선택지·입력·안내         │
│  └─ 오류 메시지              │
│                              │
├──────────────────────────────┤
│ 이전              다음/제출  │
└──────────────────────────────┘
```

- `.notebook-page-content`는 `min-height: 0`을 가진 세로 grid 또는 flex 컨테이너로 만듭니다.
- `.chapter-scroll-area`는 남은 높이를 차지하고 `overflow-y: auto`를 사용합니다.
- `.chapter-actions`는 스크롤 영역 밖의 마지막 행에 둡니다.
- 인트로 CTA, 질문 이전·다음, 신청 이전·다음·제출과 완료 버튼을 모두 같은 행동 영역 규칙으로 통일합니다.
- 행동 영역 위에는 콘텐츠와 구분되는 1px 경계 또는 배경 그라데이션을 필요할 때만 사용합니다.
- 현재 데스크톱 행동 영역에 적용된 `position: sticky`는 제거합니다. 고정된 grid 행이 같은 역할을 담당합니다.

| 완료 | 접수번호가 길어져도 본문에서 처리하고 다시 시작 버튼은 하단에 배치 |

## 8. 스크롤·포커스 기준

- 챕터에 처음 들어오면 본문 스크롤 위치를 맨 위로 초기화합니다.
- 이전 화면으로 돌아갈 때도 제목을 먼저 읽을 수 있도록 기본값은 맨 위입니다.
- 오류가 발생하면 해당 입력 또는 오류 메시지가 내부 스크롤 영역에 보이도록 `scrollIntoView({ block: 'nearest' })`를 사용합니다.
- 기타 입력을 펼칠 때 입력란이 하단 행동 영역에 가려지지 않게 합니다.
- 스크롤 영역에는 키보드 사용자를 위한 접근 가능한 이름과 필요한 경우 `tabIndex="0"`을 제공합니다.
- 스크롤바 공간 때문에 내용 폭이 흔들리지 않도록 지원 브라우저에서 `scrollbar-gutter: stable`을 적용합니다.
- `overscroll-behavior: contain`을 사용해 내부 스크롤 끝에서 바깥 페이지가 갑자기 움직이는 현상을 줄입니다.
- 스크롤 가능 여부를 색이나 스크롤바에만 의존하지 않습니다. 아래에 내용이 더 있으면 잘린 카드나 여백 흐름으로 이어짐을 알 수 있어야 합니다.

## 9. 접근성·모바일 기준

- 모바일 키보드가 열렸을 때 `100dvh` 변화에 맞춰 패널 높이를 다시 계산합니다.
- 입력 포커스, 오류 메시지와 다음·제출 버튼에 키보드와 화면 낭독기로 접근할 수 있어야 합니다.
- 브라우저 200% 확대에서도 버튼과 본문이 겹치지 않습니다.
- 패널에 `overflow: hidden`을 적용하더라도 실제 콘텐츠는 반드시 내부 스크롤 영역에서 접근할 수 있어야 합니다.
- 패널 높이와 너비 변화에는 애니메이션을 적용하지 않습니다.
- `prefers-reduced-motion`에서도 기능과 위치 관계가 동일해야 합니다.

## 11-1. 구현 결과 (2026-09-04)

- `--app-frame-height: clamp(320px, calc(100dvh - Xpx), 640px)`를 도입했습니다(모바일 112px, 태블릿 120px, 데스크톱 160px). `.app-panel`은 `min-height` 대신 고정 `height`와 `overflow: hidden`을 사용합니다.
- 모든 챕터의 `.notebook-page-content`를 `min-height: 0`의 세로 flex 컨테이너로 바꾸고, 내부에 `.chapter-scroll-area`(`flex: 1; overflow-y: auto; overscroll-behavior: contain; scrollbar-gutter: stable`)를 추가해 캡션·제목·본문·오류 메시지를 감쌌습니다. 이전·다음·제출 버튼 영역은 스크롤 영역 밖의 형제 요소로 유지해 항상 패널 하단에 보입니다.
- 신청 3단계는 각 `<form>` 안에 `.chapter-scroll-area`(헤더+오류+필드)와 액션 바를 함께 두어, 폼 제출·Enter 키 동작을 유지하면서 같은 구조를 공유합니다.
- 데스크톱 전용 `position: sticky` 행동 영역과 `height < 640px`에서의 `min-height: auto` 예외를 모두 제거했습니다. 고정 높이 패널이 항상 같은 역할을 하기 때문입니다.
- 챕터 전환 시 `chapterScrollRef.scrollTo({ top: 0 })`로 내부 스크롤을 초기화합니다. 오류·기타 입력 포커스 지점에는 `focusWithinChapter()` 헬퍼(포커스 + `scrollIntoView({ block: 'nearest' })`)를 적용했습니다.
- 브라우저에서 `getBoundingClientRect()`로 직접 측정한 결과: 1280×720에서 인트로~신청 1/3까지 8개 챕터가 모두 560×560px, 375×812에서 335×640px로 동일했습니다. 습관 카드 9개, 기타 입력 펼침 상태에서도 패널 크기는 그대로였고 본문만 스크롤됐습니다.
- `npm test`(20개), `npm run lint`, `npm run build`를 통과했습니다.

- [x] 챕터에 들어오면 내부 스크롤이 맨 위에서 시작한다. (`chapterScrollRef.scrollTo({top:0})`를 `[view]` 변경 시 실행)
- [x] 320×568, 375×812(모바일 기준), 1280×720에서 패널 크기가 챕터별로 동일하다. 390×844·820×1180·1440×900은 자동화로 직접 측정하지 못했으나 동일한 반응형 계산식을 사용하므로 같은 결과가 예상됩니다.
- [ ] 200% 확대와 실제 모바일 키보드 상태는 브라우저 자동화로 확인하지 못했습니다. 실기기 검수가 필요합니다.
- [x] 대표 viewport(1280×720, 375×812)에서 바깥 문서와 패널 내부의 이중 스크롤이 발생하지 않는다. `.app-panel`에 `overflow:hidden`을 적용해 바깥 문서는 스크롤되지 않고 `.chapter-scroll-area`만 스크롤됩니다.

## 13. 검수 방법

각 대표 viewport에서 모든 챕터를 순서대로 열고 `.app-panel.getBoundingClientRect()`의 `width`와 `height`를 기록합니다. 같은 viewport의 최댓값과 최솟값 차이가 각각 `1px` 이하여야 합니다.

추가로 다음 상태를 확인합니다.

- 선택하지 않은 기본 상태
- 가장 긴 선택지와 오류 문구가 표시된 상태
- 활력·피로 질문에서 `기타` 입력이 열린 상태
- 개인정보 상세가 펼쳐진 상태
- 브라우저 200% 확대 상태
- 모바일 입력 필드에 가상 키보드가 열린 상태
