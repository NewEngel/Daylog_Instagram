# 신청폼 활력·피로 상황형 선택 및 기타 입력 기획

## 2026-09-08 전체 답변 통일 후속 반영

2번·3번 문항 모두 공통 2열 답변 UI를 사용합니다. 버튼 모양·체크·포커스의 현재 기준은 [전체 답변 UI 통일 명세](신청-폼-UX-단순화-2차-개편-기획.md)를 따릅니다. 아래 3번 문항만 적용했던 범위는 후속 요청으로 확대되었습니다.

## 2026-09-08 3번 문항 답변 배치

사용자 요청에 따라 화면의 3번 문항 `어떤 순간에 가장 힘이 빠지나요?`(질문 02-B) 답변을 한 줄에 2개씩 배치합니다. 프리셋 7개와 기타 1개는 2열 × 4행이며, 답변이 늘어나면 행을 추가합니다.

- 기타 입력란은 그리드 아래 전체 너비로 열립니다. 단일 선택·입력·검증 동작을 유지합니다.
- 2번 문항의 답변 배치는 유지합니다.

## 1. 문서 목적

현재 `새벽`, `아침`, `점심`, `저녁`, `밤`, `출퇴근길`, `매일 달라요`로 구성된 활력·피로 답변을 실제 생활 상황 중심의 선택지로 바꿉니다. 미리 준비한 선택지에 맞는 답이 없는 사용자는 `기타`를 선택한 뒤 자신의 상황을 직접 적을 수 있게 합니다.

앞 질문인 `요즘 하루는 언제 가장 잘 움직이나요?`가 이미 하루의 시간대와 리듬을 묻고 있으므로, 이번 두 질문은 같은 시간대를 반복해서 묻지 않고 **힘이 생기거나 빠지는 조건**을 수집하는 데 집중합니다.

## 2. 현재 문제

| 문제 | 현재 상태 | 사용자에게 생기는 어려움 |
| --- | --- | --- |
| 질문 중복 | 앞 질문과 활력 질문이 모두 시간대를 물음 | 같은 답을 반복해서 고르는 느낌이 생김 |
| 기준 혼합 | `새벽·아침·점심·저녁·밤`은 시간대, `출퇴근길`은 상황 | 어떤 기준으로 골라야 하는지 불분명함 |
| 시간대 누락 | 피로가 흔한 `오후` 선택지가 없음 | 가까운 답을 고르기 어려움 |
| 예외 입력 불가 | 준비된 7개 버튼 외에는 답할 수 없음 | 실제 생활 맥락이 선택지와 다르면 정보가 사라짐 |
| 불확실성과 예외의 혼동 | `매일 달라요`만 제공 | 패턴이 변하는 경우와 목록에 답이 없는 경우를 구분하지 못함 |

## 3. 개편 원칙

1. 활력과 피로 질문은 시간대가 아니라 생활 속 **순간과 조건**을 묻습니다.
2. 두 화면은 서로 다른 상황형 선택지를 사용합니다.
3. 버튼 문구는 한 번에 이해할 수 있는 일상어로 작성합니다.
4. `날마다 달라요`는 패턴이 일정하지 않은 사용자를 위해 유지합니다.
5. 기존 `잘 모르겠어요`는 제거하고 마지막에 `기타`를 둡니다.
6. `기타`를 선택하면 직접 입력란을 펼칩니다.
7. 한 화면에서는 하나의 답만 선택합니다.

## 5. 기타 직접 입력

### 5.1 동작

- `기타` 버튼은 각 목록의 마지막에 배치합니다.
- `기타`를 선택하면 버튼 목록 바로 아래에 한 줄 텍스트 입력을 펼칩니다.
- 입력란이 열리면 사용자가 버튼을 눌러 연 동작에 한해 입력란으로 포커스를 이동합니다.
- `기타`를 선택한 것만으로는 답변 완료로 처리하지 않습니다.
- 공백을 제외한 글자가 1자 이상 있어야 다음 화면으로 이동할 수 있습니다.
- 입력은 앞뒤 공백을 제거한 뒤 최대 50자까지 받습니다.
- 다른 버튼으로 바꾸면 입력란은 숨기되, 같은 방문 안에서는 작성한 내용을 임시로 보존합니다.
- 다시 `기타`를 선택하면 이전에 작성한 내용을 복원합니다.

### 5.2 입력 문구

| 화면 | 입력 라벨 | 예시 문구 |
| --- | --- | --- |
| 힘이 나는 순간 | 힘이 나는 다른 순간 | 예: 음악을 들으며 걸을 때 |
| 힘이 빠지는 순간 | 힘이 빠지는 다른 순간 | 예: 여러 약속이 이어질 때 |

입력란 아래에 현재 글자 수를 계속 표시하지는 않습니다. 50자를 넘겼을 때만 오류를 보여주거나 HTML `maxLength`로 추가 입력을 막습니다.

### 5.3 오류 문구

| 상황 | 오류 문구 | 포커스 이동 |
| --- | --- | --- |
| 아무 버튼도 선택하지 않음 | 가장 가까운 순간을 하나 골라주세요. | 첫 번째 버튼 또는 질문 그룹 |
| `기타`만 선택하고 비워둠 | 기타로 답할 순간을 짧게 적어주세요. | 직접 입력란 |
| 공백만 입력함 | 기타로 답할 순간을 짧게 적어주세요. | 직접 입력란 |
| 50자 초과 | 50자 이내로 적어주세요. | 직접 입력란 |

## 6. 선택 상태와 접근성

- `기타`도 다른 답변과 동일한 라디오 버튼 그룹에 포함합니다.
- `기타` 선택 상태는 다른 버튼과 같은 Yellow 배경, Deep Navy 테두리로 표시합니다.
- 펼쳐지는 입력에는 화면별로 다른 시각적 라벨을 항상 표시하고 placeholder만으로 의미를 전달하지 않습니다.
- 입력란은 질문 설명과 오류 문구에 `aria-describedby`로 연결합니다.
- 오류 발생 시 메시지를 표시한 뒤 입력란에 포커스를 옮깁니다.
- 입력란을 숨길 때 `display: none` 또는 조건부 렌더링을 사용해 키보드 탐색 순서에서 제거합니다.
- 모바일 키보드가 열려도 입력란과 다음 버튼까지 문서 스크롤로 접근할 수 있어야 합니다.

## 7. 데이터 처리

### 7.1 제출값

기존 `comfortableTime`과 `difficultTime` 필드를 유지합니다.

| 선택 유형 | 제출값 예시 |
| --- | --- |
| 준비된 버튼 | `혼자 집중할 때` |
| `날마다 달라요` | `날마다 달라요` |
| `기타` 직접 입력 | `기타: 음악을 들으며 걸을 때` |

`기타: ` 접두사를 포함해도 서버의 기존 100자 제한 안에 들어가도록 사용자 입력은 50자로 제한합니다. 접두사를 붙이면 운영자가 Google Sheets에서 준비된 선택과 직접 입력을 구분할 수 있습니다.

### 7.2 화면 상태

현재 구현은 저장된 문자열과 버튼 라벨이 같은지를 비교해 선택 상태를 표시합니다. `기타: 입력값`은 버튼 라벨 `기타`와 일치하지 않으므로, 다음 상태를 별도로 관리해야 합니다.

- 힘이 나는 순간의 선택 ID와 기타 입력 초안
- 힘이 빠지는 순간의 선택 ID와 기타 입력 초안
- 최종 제출에 사용할 기존 문자열 필드 2개

뒤로 갔다가 돌아오거나 새로고침해도 `기타` 선택과 입력값이 복원되어야 합니다. 클라이언트 임시 상태를 제출 payload와 분리하거나, `기타: ` 접두사를 읽어 화면 상태를 복원하는 방식 중 하나로 구현합니다. 제출 payload에는 기존 계약에 정의된 필드만 포함합니다.

### 7.3 계약 영향

- `comfortableTime`과 `difficultTime`은 현재 API와 Apps Script에서 1~100자의 문자열로 검증하므로 스키마 버전을 올릴 필요가 없습니다.
- Google Sheets 열과 Apps Script 저장 순서도 유지합니다.
- 프론트의 공통 `energyTimeOptions`는 화면별 목록인 `energyBoostOptions`, `energyDrainOptions`로 분리합니다.
- 현재 `EnergyTimeSlot` 타입은 두 목록의 ID 타입으로 분리하거나 공통 문자열 ID 타입으로 재정의합니다.
- 제출 전 `answers` 객체를 그대로 펼치는 현재 방식에서는 UI 전용 상태가 외부 payload에 섞이지 않도록 별도 상태로 두거나 payload를 명시적으로 구성합니다.

## 8. UI 배치

- 모바일에서는 버튼이 자연스럽게 줄바꿈되는 pill 목록을 유지합니다.
- `기타` 입력은 버튼 너비와 관계없이 다음 줄의 전체 폭을 사용합니다.
- 입력란이 열릴 때 가운데 패널은 고정 높이 안에서 내용을 자르지 않고 아래로 확장합니다.
- 직접 입력 때문에 다음 버튼이 밀려나도 패널 내부 스크롤을 만들지 않습니다.
- 입력란 등장에 높이 애니메이션을 강제하지 않습니다. 필요한 경우 `opacity`만 짧게 사용하고 `prefers-reduced-motion`에서는 제거합니다.
