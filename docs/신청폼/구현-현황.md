# 신청폼 구현 현황

## 현재 상태

React, TypeScript와 Vite 기반 초기 신청 경험을 구현했습니다. 배포 대상은 Vercel이며, 최종 신청과 퍼널 이벤트는 동일 출처 Serverless Function을 거쳐 기존 통합 Google Apps Script로 전달하도록 구성했습니다.

신청 경험은 `5단계 생활 기록 → LIFE SESSION 안내 → 신청 정보 입력(3단계) → 신청 완료` 흐름입니다. 별도 LIFE NOTE 답변 요약 화면은 사용하지 않습니다.

구현 경로:

```text
application-form/
```

## 브랜드 경험

2026-09-03부터 신청폼은 실제 노트 모양에서 벗어난 **카드 기반 라이트 인터페이스**를 사용합니다. `LIFE NOTE`는 물리적 노트 장식이 아니라 내 하루를 짧게 정리하는 경험명으로 유지합니다.

- 전체 화면에서 브랜드 문장을 강하게 제시하는 인트로
- 카드 안의 중앙 로고와 질문·신청의 단일 진행 막대
- 한 번에 하나의 질문에 집중하는 흐름
- Clean White 카드, Warm Ivory 보조면과 넉넉한 여백
- 모든 주 행동에 사용하는 Growth Yellow CTA
- Sage Green 체크 원으로 표시하는 신청 완료 상태
- 선택 카드의 장식용 번호·영문 배지는 사용하지 않고 체크와 순위처럼 기능에 필요한 상태만 표시

스프링, 종이 가로줄, 붉은 여백선, 포스트잇 인덱스, 종이 스택과 페이지 넘김 모션은 제거했습니다. 스마트폰 베젤, 코치 사진과 인물 중심 Hero도 사용하지 않습니다.

첫 화면은 목적 카드와 `5개 질문·약 3분·대면 체험 신청` 정보 카드로 구성합니다. 로고와 진행 정보를 페이지 바탕 위에 직접 배치하고, 질문은 `n / 5`, 신청은 `n / 3` 노란 진행 막대를 표시합니다. 질문 제목은 가운데 정렬합니다. 전체 생활 질문과 일정 선택은 공통 `AnswerChoice` 컴포넌트로 같은 너비의 2열·최소 높이 56px·8px 간격을 사용하며, 오른쪽에 체크 또는 습관 순위를 표시합니다. 습관 순위 선택, 기타 입력, 기본 정보·일정·개인정보 동의 3단계는 유지합니다.

2026-09-08 이미지 초안에 따라 모든 화면의 패널 최대 폭을 440px, 최대 높이를 680px로 변경했습니다. 같은 viewport에서는 모든 챕터가 동일한 크기이며, 본문만 내부 스크롤되고 행동 버튼은 하단에 유지됩니다. 후속 요청에 따라 바깥 흰 카드 배경·테두리·모서리·그림자를 제거하고 투명한 레이아웃 컨테이너로 유지합니다. 선택지와 입력칸은 기존 형태를 유지합니다. 정확한 반응형 치수는 [중앙 패널 명세](../04-디자인/신청폼-중앙-패널-비율-일관화-기획.md)를 따릅니다.

완료 화면에는 세이지색 기하학 도형과 일정 안내 카드를 표시합니다. 신청 내역은 기본 접힘 상태이고, 펼치면 기존 신청 번호·복사 버튼·프로그램 정보를 확인할 수 있습니다. UI 버전은 `2026.09.4`, 데이터 스키마는 기존 v3입니다.

사용자 노출 문구는 중학생이 배경지식 없이 이해할 수 있는 일상어를 사용합니다. 오류에는 해결 행동을 함께 표시하며, 신청 정보 오류는 상단 요약과 해당 필드 아래에서 동시에 확인할 수 있습니다. 연락 기한, 나이 기준, 지역·비용과 개인정보 문의 정보는 운영 확정 전이라 최종 카피에서 보류했습니다.

## 화면 흐름

```text
인트로
  → 하루 리듬
  → 힘이 나는 순간
  → 힘이 빠지는 순간
  → 집중이 잘되었던 때
  → 변화하고 싶은 습관 순위
  → LIFE SESSION 프로그램 안내
  → 신청 1/3 기본 정보
  → 신청 2/3 가능한 일정
  → 신청 3/3 개인정보 동의
  → 신청 완료
```

## 구현된 질문

| 단계 | 질문 | 입력 방식 |
| --- | --- | --- |
| 1 | 요즘 하루는 언제 가장 잘 움직이나요? | 단일 선택 |
| 2 | 어떤 순간에 가장 힘이 나나요? | 생활 상황 버튼 7개 + 기타 직접 입력(최대 50자) |
| 3 | 어떤 순간에 가장 힘이 빠지나요? | 생활 상황 버튼 7개 + 기타 직접 입력(최대 50자) |
| 4 | 집중이 가장 잘되었던 때는? | 단일 선택 |
| 5 | 지금 가장 변화되고 싶은 습관은? | 누른 순서대로 1~3순위 선택 |

2, 3단계의 `기타` 입력은 `기타: <내용>` 형식으로 기존 `comfortableTime`/`difficultTime` 문자열 필드에 담기며, 데이터 스키마는 변경하지 않습니다.

## 연락 신청 항목

신청 정보 입력은 `기본 정보 → 가능한 일정 → 개인정보 동의` 3단계 화면으로 나뉘며, 화면마다 자체 다음/제출 버튼과 유효성 검증을 가집니다.

- 필수: 이름
- 필수: 나이
- 필수: 전화번호(`010-0000-0000`)
- 필수: 거주지 주변 역
- 필수: 인터뷰 가능 요일과 시간대
- 필수: 개인정보 수집·이용 동의
- 사용자에게 보이지 않는 스팸 방지 필드

개인정보 안내에는 실제 수집 항목, 체험 프로그램 신청·인터뷰 안내 목적과 신청일로부터 3개월 보유 기간을 표시합니다.

## 데이터 처리

- 생활 탐색 답변만 `sessionStorage`에 임시 저장합니다.
- 신청 개인정보는 브라우저 저장소에 저장하지 않습니다.
- 제출 재시도 시 같은 접수번호를 사용합니다.
- 퍼널 이벤트에는 질문 답변과 개인정보를 넣지 않습니다.
- Vercel API에서 허용값, 길이, 연락처 형식과 식별자 형식을 재검증합니다.
- Apps Script 비밀값과 URL은 서버 환경변수에서만 읽습니다.
- Google Sheets에는 접수번호와 이벤트 ID 기준 중복 방지를 적용합니다.
- 데이터 스키마는 `daylog-life-session-v3`를 사용합니다.
- 퍼널은 9단계(`started` → 5개 질문 이벤트, 단 힘이 나는/빠지는 순간은 두 화면을 합쳐 `energy_selected` 1회 → `session_info_viewed` → `application_started` → `consent_accepted` → `submitted`)로 구성됩니다.
- `npm test`의 20개 계약·API 테스트가 프론트·API·Apps Script의 스키마, 문자열 시간, 기타 입력 payload 제외, 순위 데이터, 신청 필드, 퍼널 순서와 재시작 ID 회귀를 검사합니다.

## 반응형 UI

- 전체 화면은 Soft White Gray `#F6F7F5`, 카드와 입력은 Clean White, 보조 안내는 Warm Ivory를 사용합니다.
- 280px에서도 강제 최소 너비 없이 자연스럽게 리플로우하고 가로 넘침이 발생하지 않습니다.
- 화면 좌우 여백은 359px 이하 16px, 360px 이상 20px, 600px 이상 24px을 기준으로 합니다.
- 1280×720 화면에서 첫 화면 CTA가 스크롤 전에 보입니다.
- 599px 이하 질문 화면에서는 일반 선택 카드를 읽기 쉬운 1열, 생활 영역을 2열로 배치합니다.
- 359px 이하에서는 생활 영역과 신청 기본 정보도 1열로 배치합니다.
- 600px 이상에서는 생활 영역을 3열, 신청 기본 정보를 2열로 배치합니다.
- 700px 이하의 낮은 화면에서도 글자를 과도하게 줄이지 않고 필요한 세로 스크롤을 허용합니다.
- 모바일 기준은 한 화면 무스크롤이 아니라 가로 잘림 방지, 자연스러운 세로 스크롤, 가상 키보드가 입력과 제출 행동을 가리지 않는 것입니다.
- 선택 상태는 옅은 Yellow 배경, 2px Deep Navy 테두리와 체크 또는 순위 문구로 구분합니다.
- 커스텀 선택 카드와 입력 필드는 3px Deep Navy 포커스 외곽선을 사용합니다.
- 599px 이하에서 긴 이전·다음 버튼은 세로로 배치하고 모든 조작 영역을 44px 이상으로 유지합니다.
- `prefers-reduced-motion`에서는 전환 이동 시간을 사실상 제거합니다.
